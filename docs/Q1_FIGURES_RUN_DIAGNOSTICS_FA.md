# V8 / اصلاح توقف مبهم اجرا و نمودارهای مقاله (بدون تغییر هسته علمی)

## به‌روزرسانی پژوهشی

فایل علمی `mbmf_q1_final_v7.py`، هفت مدل، baselineها، ماتریس شش دیتاست، تنظیمات K و seed، ۳۸ ابلیشن و توابع آموزش/زیان تغییر نکرده‌اند. تغییرات فقط در CLI، خلاصه‌سازی Pandas و visualization هستند.

## معنی هشدارهای دیده‌شده

- `Sparse CSR tensor support is in beta`: هشدار کتابخانه PyTorch است، نه خطا یا نشانه فساد نتایج. آزمون هم‌ارزی dense/sparse در self-test همچنان اجرا می‌شود.
- `NumPy array is not writable`: هنگام استفاده از `torch.as_tensor` روی آرایه فقط‌خواندنی Pandas در **هسته علمی frozen** رخ می‌دهد. طبق مسیر فعلی، اندیس‌ها و امتیازها برای خواندن استفاده می‌شوند. به‌جای خاموش کردن بی‌دلیل هشدار، هسته را دست‌نخورده نگه داشتیم. برای حذف خودِ هشدار باید به‌صورت تغییرِ کنترل‌شده هسته، با به‌روزرسانی SHA و تست هم‌ارزی جداگانه عمل کرد.
- `DataFrame is highly fragmented`: ساخت یک‌باره بلوک‌های آماری جایگزین روش قبلی شد؛ مقدار میانگین/انحراف معیار/تعداد نمونه و کلیدهای گروه‌بندی عوض نشده‌اند.

هیچ‌کدام از هشدارها به‌تنهایی «اجرا کامل شده» یا «اجرا متوقف شده» را ثابت نمی‌کنند.

## تشخیص قطعی وضعیت اجرا

از شاخه main جدید:

```powershell
python run_v8.py --dataset ml-100k --data-root ./datasets --split-seeds 2026 --model-seeds 11 --k 10 --quick --output ./results_q1_v8/laptop_pilot
$LASTEXITCODE
Get-Content ./results_q1_v8/laptop_pilot/run_status_v8.json
Test-Path ./results_q1_v8/laptop_pilot/locked_test_runs.csv
```

- `status: COMPLETED` و exit code صفر به معنی پایان مسیر اجرا و رسم شکل‌هاست.
- `status: FAILED`، متن `error` و `traceback` را بررسی کنید. اگر PowerShell/پردازش با kill/OOM خاتمه پیدا کند، ممکن است `status: RUNNING` باقی بماند؛ این هم نشانه عدم اتمام است.
- وجود پوشه `figures` بدون تکمیل `locked_test_runs.csv` یا `run_status_v8.json` به تنهایی اثبات صحت مطالعه نیست.

## نمودارهای جدید

مجموعه `q1_*` با خروجی PNG (۳۲۰ DPI) و PDF برداری:

- Dot/rank plot هر معیار با عدد دقیق و رنگ پایدار برای هر روش؛ CI یا SD تنها در صورت وجود تکرار واقعی.
- Train / Validation / Locked Test RMSE و منحنی یادگیری.
- Efficiency–Accuracy و NDCG@k با برچسب صریح «فقط اقلام امتیازدار کنارگذاشته‌شده».
- توزیع تجمعی خطای مطلق، MAE به تفکیک امتیاز واقعی، boxplot باقیمانده‌ها از فایل‌های test prediction واقعی.
- برای ablation، یک نمودار مستقل برای هر خانواده مدل برحسب اختلاف RMSE با full همان خانواده.
- وقتی چند دیتاست اجرا شوند، heatmap بین‌دیتاستی با رتبه نسبی در هر دیتاست و مقدار RMSE در سلول‌ها.
- فایل `figure_manifest.json` منابع و محدودیت‌های علمی هر شکل را توضیح می‌دهد.

در اجرای یک seed، آزمون معناداری بین splitها قابل اتکا نیست؛ هیچ CI یا نتیجه‌ی معناداری ساختگی تولید نمی‌شود.

نمودارهای K-sensitivity، sparsity sensitivity و ablation صرفاً زمانی تولید می‌شوند که آزمایش متناظرشان واقعاً اجرا شده باشد.

## کنترل هش هسته علمی، اصلاح تکمیلی

در لاگ کاربر، SHA هسته برابر `8c29289c...` دیده شد، در حالی‌که نسخه پین‌شده ریپو `6da726cb...` است. نسخه جدید **هش واقعی فایل را با `SCIENTIFIC_CORE_MANIFEST_V8.json` تطبیق می‌دهد** و اگر برابر نباشند، قبل از آموزش خطا می‌دهد. قبلاً آزمون فقط هش زمان import را دوباره مقایسه می‌کرد و ممکن بود تغییر محلی قبل از import را قبول کند. برای بررسی ایمن در لپ‌تاپ:

```powershell
git status
git diff -- mbmf_q1_final_v7.py
Get-FileHash -Algorithm SHA256 .\mbmf_q1_final_v7.py
```

اگر تغییر شخصی ضروری است، نخست تفاوت را مستندسازی و نسخه جدا بسازید؛ بدون بررسی فایل علمی محلی را پاک یا overwrite نکنید. تا هنگام تأیید و تثبیت نسخه، نتایج آن را با نتایج scientific-core اصلی مخلوط نکنید.
