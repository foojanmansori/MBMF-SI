**دامنه و سیاست تغییر:** این بسته از ZIP اصلی V8 ساخته شده است. هیچ تغییری در `mbmf_q1_final_v7.py`، کلاس‌ها و فرمول‌های Methods 1–7، شش دیتاست و بازه‌های رسمی آنها، ماتریس دیتاست–روش، ۳۸ ابلیشن، مقادیر پیش‌فرض تنظیمات علمی و شبکه اسکن پارامترها داده نشده است. گزارش `PROTOCOL_IMMUTABILITY_REPORT_8.0.1.json` به صورت ماشینی این مقایسه را ثبت می‌کند.

## مواردی که عمداً دست‌نخورده ماندند

- فایل علمی V7 با SHA-256 برابر `6da726cb155ab6ad291f5f608febc37f42d1c25ac3924910f56917908c1f124c`.
- نام و ایده Methods 1–7 و baselineها، مقدار Kهای اصلی (10/20/50)، ساختار loss و optimizer علمی، seedهای پیش‌فرض، ابلیشن‌های ۳۸گانه و sweepهای hyperparameter.
- دیتاست‌های Synthetic، Jester، Book-Crossing، ML-100K، ML-1M و ML-10M؛ هیچ دیتاست اضافه/حذف نشده است.
- محاسبه ranking هنوز **held-out explicit/testset** است؛ در V8 اولیه هم همین بود. این متریک معادل full-catalog ranking نیست؛ نباید بدون تعریف دقیق پروتکل در مقاله گزارش شود.
- BMC-ADMM، Deep-MMMF و DRPRA همچنان به کد نویسندگان و predictionهای واقعی نیاز دارند. آن کدها را عمداً جعل یا با جایگزین‌های ضعیف‌تر تعویض نکردیم.

## آزمون‌های انجام‌شده

- ۳۵ تست غیر‌یکپارچگی + ۲ تست integration موفق (شامل ۱۳ تست رگرسیون جدید).
- روی Synthetic با بازه منفی و هر دو backend dense/sparse، هر سه MBMF-F/C/N با موفقیت آموزش، پیش‌بینی و save/load شدند.
- یک گام بهینه‌سازی MBMF-F/C/N با backendهای dense و sparse اختلاف پارامتری در حد تلورانس عددی نشان داد.
- در مطالعه Synthetic با تنظیم CLI سریع، برای ۱۲ روش تعریف‌شده آن دیتاست، RMSEهای train/val/test متناهی و ستون‌های عدم‌قطعیت Method7 ایجاد شدند؛ `audit_results_v8.py` برای پوشه اجرای آن خطای completeness پیدا نکرد و هشدار pilot بودن داد. خروجی CLI بزرگ در این محیط در مرحله تولید شکل‌ها با محدودیت زمان مواجه شد؛ **نباید این مورد را به‌عنوان اجرای کامل نهایی CLI یا مقاله معرفی کرد.**

## کارهای باقی‌مانده قبل از مقاله Q1

۱. دانلود دیتاست‌های واقعی با نسخه/فایل مشخص، ثبت SHA256 داده‌های خام و اجرای کامل پنج split و پنج model seed و Kهای مقرر. این ZIP نتایج واقعی این اجراها را ندارد.

۲. اجرای author code برای سه رقیب بیرونی با splitهای دقیق استخراج‌شده؛ ذخیره نسخه و هش کد رقبا و فایل‌های پیش‌بینی؛ محاسبه مجدد متریک‌ها از predictionهای واقعی.

۳. تکمیل اجراهای همه ۳۸ ابلیشن روی پروتکل اصلی؛ انجام اسکن **فقط validation**؛ سپس run نهایی با پارامتر انتخاب‌شده و test قفل‌شده.

۴. تفکیک روشن نتایج ranking روی held-out explicit از full-catalog ranking در مقاله. اگر full-catalog مورد نیاز هدف تحقیق است، باید به‌عنوان مطالعه دیگری با پروتکل تعریف‌شده اجرا شود (در این بسته عمداً به اهداف آزمایش تغییری داده نشده است).

۵. صحت‌سنجی سخت‌افزار، مقدار منابع و تمامی جدول/شکل‌ها در اجرای واقعی؛ گزارش paired seeds و محدودیت‌های فرض استقلال در آزمون‌های آماری.

## دستور اجرای بررسی پس از مطالعه

```bash
python -m pytest -q
python run_v8.py --self-test-only
python run_v8.py --dataset ml-1m --data-root ./datasets --output ./results_q1_v8/ml-1m
python audit_results_v8.py --study ./results_q1_v8/ml-1m --report ./results_q1_v8/ml-1m/Q1_COMPLETENESS_AUDIT.json
```
